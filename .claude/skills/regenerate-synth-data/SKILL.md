# regenerate-synth-data

All datasets in `datasets/` are generated by `src/cdisc_generation_functions.py` and committed.
Never hand-edit a CSV; change the generator and regenerate.

## 1. Regenerate

Always use the project venv (not system `python3`):

```bash
.venv/bin/python src/cdisc_generation_functions.py
```

The `__main__` block seeds `np.random.seed(0)`, so output is deterministic: running it on a
clean tree must leave `git status` clean. If it does not, something nondeterministic crept in.

## 2. Call order matters

Functions consume each other's output; `__main__` defines the order and is the source of truth:

`create_dm → create_ex → derive_events → finalize_ex → create_tr → derive_rs → create_tu →
finalize_dm → create_ds → apply_fatal_ae → create_fa → create_relrec → create_adsl →
create_adtte`, plus independent `create_tv` / `create_ta`.

- `finalize_ex` / `finalize_dm` are second passes that need `derive_events` output. Don't reorder.
- `create_fa(ds, ae)` needs the AE frame from `apply_fatal_ae`; `create_relrec` needs FA's `_DSSEQ`.
- When adding a function, add it to the `__main__` block *and* to the CSV write list there.
- Helper columns (`DM.TRT01A`, `FA._DSSEQ`) are dropped at write time; add new internal
  columns to that drop list.

## 3. Keep the seeded stream stable

Every `np.random` draw shifts all later draws, which changes subjects across *every* dataset.

- Prefer deterministic logic for new content (sort + pick, derive from existing columns), as
  `apply_fatal_ae` and `_death_cause` do.
- If a new random draw is unavoidable, expect widespread diffs and re-check PFS fidelity.
- Tumour scan timing uses `_FIRST_SCAN_DAY` / `_SCAN_INTERVAL_DAYS`; progression dates are
  snapped onto that schedule. Change the constants, never hardcode 85 / 84.
- `_PROG` is calibrated so observed median PFS matches the published 10.3 vs 5.1 months.
  Changing progression or censoring logic can fail the PFS fidelity check.

## 4. Confirm only the intended files changed

```bash
git diff --stat datasets/
```

Compare against what the change should touch (e.g. an FA-only change should leave DM, EX, TR,
RS, ADSL, ADTTE byte-identical). An unexpected diff in another dataset usually means an
accidental extra random draw or a reordered call.

## 5. Test and validate

Run `.venv/bin/python -m pytest` first. `tests/test_committed_data.py` fails if the committed CSVs differ from a fresh regeneration, so it also confirms you regenerated and committed the data. If you add a function, route it through `generate_all()` and add an invariant test for any new cross-domain relationship.

Then use the `validate-synth-data` skill, or run directly:

```bash
.venv/bin/python .claude/skills/validate-synth-data/scripts/validate.py --datasets datasets/ --output validation_report.md
```

All checks must pass. If you added a new cross-domain relationship, add a check for it in
`validate.py` (see `check_timeline_death` for death/AE/FA examples), then update the check
count in `.claude/skills/validate-synth-data/SKILL.md` and `README.md`, and mirror skill edits
to `~/.claude/skills/validate-synth-data/`.

## 6. Commit

- Commit generator change, regenerated `datasets/*.csv` and `validation_report.md` together.
- STUDYID is always `NCT01797120` and `USUBJID` is `NCT01797120-NNNN`.
- Lint runs in CI: `.venv/bin/pre-commit run --all-files` (black + flake8, line length 120).
- CORE conformance rules are not run by the validator; say so in the PR if you did not run them.
